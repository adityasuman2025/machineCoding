# Workspace Rules

- **Thorough Code Reviews**: Always analyze and review both high-level architecture (rendering lifecycles, state ownership, prop-drilling, following best market practices for architectural design) and low-level / mathematical / localized optimizations (algorithms, math simplifications, clean conditionals) in every code review. Do not focus solely on architectural correctness.
- **No Hardcoded Strings**: Verify that no hardcoded strings are present in key logic. Ensure separate, meaningful constants are created and reused.
- **Utility Function Scope**: Ensure helper/utility functions are kept outside the component's render scope (if they don't depend on component state or props) to prevent recreating their function references on every re-render.
- **State Management Verification**: Check for correct state ownership, unified state updates (reducing multiple state updates when a single atomic update is possible), and ensure there are no derived state synchronization hooks (such as setting state in `useEffect` on prop change).
- **Functionality & Edge Cases**: Systematically analyze edge cases, missing user interactions (e.g. key navigation, mouse out of container, paste handlers), and ensure robust event handling across mobile and desktop.
- **Scalability, Reusability, Extensibility & Modularity**: Verify that magic values/sizes are exposed via props instead of hardcoded constants, code is modularized by separating UI presentation from business logic/utils, and components are built to scale and be reused across different scopes under different configurations.
- **React Anti-Patterns, Market Practices & Coding Standards**: Actively audit code for common React anti-patterns (such as mutating refs during render, inline object creations in props, unstable keys, or triggering side-effects inside state updaters), ensure alignment with modern market standards (like lazy state initializers, custom hook encapsulation), enforce clean TypeScript conventions, and never suggest a solution that introduces React anti-patterns.
- **Continuous Architectural & Performance Auditing**: Always proactively evaluate if the implementation can be further improved in terms of architecture, state management, scalability, rendering performance, and market standards, providing actionable optimization suggestions.
- **Accessibility & WAI-ARIA Standards (a11y)**: Systematically audit and enforce modern market accessibility standards across all code:
  - **Semantic HTML**: Mandatory use of semantic elements (`<main>`, `<header>`, `<footer>`, `<nav>`, `<aside>`, `<section>`, `<dialog>`, `<form>`, `<button>`, `<label>`, `<input>`, `<select>`, `<textarea>`, `<ul>`, `<ol>`, `<li>`, `<figure>`, `<figcaption>`) over generic `<div>`/`<span>` containers for interactive or structural elements.
  - **Complete WAI-ARIA Coverage (Roles, States & Properties)**:
    - *Roles*: Widget & Composite roles (`dialog`, `alertdialog`, `button`, `checkbox`, `radio`, `radiogroup`, `combobox`, `listbox`, `option`, `menu`, `menuitem`, `tab`, `tablist`, `tabpanel`, `tooltip`, `tree`, `grid`) and Landmark/Live roles (`navigation`, `main`, `banner`, `region`, `status`, `alert`, `log`).
    - *States*: `aria-expanded`, `aria-checked`, `aria-selected`, `aria-hidden`, `aria-disabled`, `aria-pressed`, `aria-current`, `aria-invalid`, `aria-busy`, `aria-modal`.
    - *Properties*: `aria-labelledby`, `aria-describedby`, `aria-controls`, `aria-live` (`polite`/`assertive`), `aria-haspopup`, `aria-required`, `aria-readonly`, `aria-valuenow`, `aria-valuemin`, `aria-valuemax`, `aria-valuetext`, `aria-label`, `aria-autocomplete`, `aria-orientation`.
  - **Keyboard Navigation & Shortcuts**: Implement full keyboard support (`Tab`, `Shift+Tab`, `Escape`, `Enter`, `Space`, Arrow keys `ArrowUp`/`ArrowDown`/`ArrowLeft`/`ArrowRight`, `Home`, `End`, `PageUp`, `PageDown`), focus trapping, focus restoration on unmount, explicit `:focus-visible` focus rings, and prevent focus traps or skipped buttons (e.g. `tabIndex={0}`).
  - **Screen Reader & Inclusive Usability**: Guarantee dynamic screen reader announcements via `aria-live` regions or `sr-only` utility classes, minimum touch target sizes (44x44px), WCAG AA color contrast (minimum 4.5:1), descriptive alt text for images, and full non-mouse input support.
