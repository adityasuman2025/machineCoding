# Workspace Rules

- **Thorough Code Reviews**: Always analyze and review both high-level architecture (rendering lifecycles, state ownership, prop-drilling, following best market practices for architectural design) and low-level / mathematical / localized optimizations (algorithms, math simplifications, clean conditionals) in every code review. Do not focus solely on architectural correctness.
- **No Hardcoded Strings**: Verify that no hardcoded strings are present in key logic. Ensure separate, meaningful constants are created and reused.
- **Utility Function Scope**: Ensure helper/utility functions are kept outside the component's render scope (if they don't depend on component state or props) to prevent recreating their function references on every re-render.
- **State Management Verification**: Check for correct state ownership, unified state updates (reducing multiple state updates when a single atomic update is possible), and ensure there are no derived state synchronization hooks (such as setting state in `useEffect` on prop change).
- **Functionality & Edge Cases**: Systematically analyze edge cases, missing user interactions (e.g. key navigation, mouse out of container, paste handlers), and ensure robust event handling across mobile and desktop.
- **Scalability, Reusability, Extensibility & Modularity**: Verify that magic values/sizes are exposed via props instead of hardcoded constants, code is modularized by separating UI presentation from business logic/utils, and components are built to scale and be reused across different scopes under different configurations.
- **React Anti-Patterns, Market Practices & Coding Standards**: Actively audit code for common React anti-patterns (such as mutating refs during render, inline object creations in props, unstable keys), ensure alignment with modern market standards (like lazy state initializers, custom hook encapsulation), and enforce clean TypeScript conventions.
